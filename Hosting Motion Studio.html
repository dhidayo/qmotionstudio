How to host and publish Motion Studio

The app needs much less than you might expect today, and much more once accounts and posting arrive. This covers both.

The short answer

  • Today you need only a domain and a static host with HTTPS. The finished app is 156 files, 12 MB in total, with no server and no database. Editing, saving and exporting all happen in the user's browser.
  • cPanel hosting is enough, but it is not what I'd choose. Every update becomes a manual upload, and someone who opens the app halfway through an upload can get a broken mix of old and new files.
  • My recommendation is GitHub plus Cloudflare Pages, with your domain staying at Namecheap. It is free, allowed for a business, has a fast global network, renews HTTPS by itself, and publishes automatically every time the code changes.
  • Two well-known free hosts don't allow a paid product. GitHub Pages forbids commercial sites, and Vercel's free plan is for personal, non-commercial use.
  • A database only comes with accounts, subscriptions and social posting. cPanel's MySQL and PHP are the wrong tools for that. Use a managed backend; I recommend Supabase.

Your options

A. GitHub + Cloudflare Pages + your Namecheap domain

recommended

Cost: $0 a month, plus the domain at roughly $10–15 a year. Unlimited bandwidth, up to 500 publishes a month, and a 25 MB limit per file, against our largest of 2 MB.

  1. Put the code on GitHub, as a private repositoryThe project is already tracked with git, so this is a single push.
  2. Create a free Cloudflare account and connect the repositoryWorkers & Pages, then Create, then Pages, then connect to GitHub and pick the repository.
  3. Enter the build settingsFramework preset Vite, build command npm run build, output folder dist, and an environment variable NODE_VERSION set to 22.
  4. Connect your domainIn the Pages project, open Custom domains and add yours. The simplest route is to point the domain's nameservers at Cloudflare from your Namecheap dashboard. The domain stays registered with Namecheap and Cloudflare handles DNS for free.
  5. Publish by pushingEvery change pushed to the main branch goes live in about a minute. Every other branch gets its own private preview address, which is how you test before your users see anything.

B. cPanel shared hosting (Namecheap, SpeedyConnect or similar)

works, with friction

Cost: whatever your hosting plan costs, often $2–10 a month. Fine for the MVP.

  1. Build on your computerRun npm run build. It creates the dist folder.
  2. Upload the contents of dist into public_htmlUse cPanel File Manager or FTP. Upload the files inside the folder, not the folder itself, and include the .htaccess I'll provide.
  3. Turn on HTTPSRun AutoSSL or Let's Encrypt in cPanel's SSL/TLS section, and redirect all visits to HTTPS (the .htaccess does this).
  4. Repeat steps 1 and 2 for every updateThis is the weak point: it is manual, there are no previews, and a half-finished upload can break the app for anyone who loads it at that moment. Shared hosts also limit file counts and rarely have a global network.

Three things to plan for before building those features

  1. Posting to social media changes the privacy promiseThe app currently says nothing leaves your device. To post through Instagram's or TikTok's API, the video has to sit at a public web address their servers can fetch, so it must be uploaded first. The honest promise becomes "nothing leaves your device unless you choose to post it". Delete each file as soon as it has been posted.
  2. Every platform must approve your app before it can post for users
    • Instagram: business and creator accounts only, after Meta reviews your app. Each account can publish up to 100 posts through the API in 24 hours.
    • TikTok: until your app passes TikTok's audit, every post it makes is forced to private and only 5 users can post per day.
    • LinkedIn, YouTube and X: each has its own approval, quota or paid API tier.
    Applying takes weeks. A posting service such as Ayrshare already holds these approvals and sells access monthly, which is the faster way to launch bulk posting. You can build your own connections later.
  3. Watermark and PRO MAX rules will run on the user's deviceExport happens in the browser, so the check for PRO and PRO MAX elements happens there too. That is enough to stop ordinary users. A technical user could get around any check that runs on their own machine, which is normal for apps like this, but it means PRO MAX limits are a deterrent rather than a lock. The only true lock would be rendering on your servers, which costs money for every video.
